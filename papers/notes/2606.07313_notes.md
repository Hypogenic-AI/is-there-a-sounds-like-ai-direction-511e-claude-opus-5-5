# SV-Detect: AI-generated Text Detection with Steering Vectors (arXiv 2606.07313v2, Sep 2026)

Authors: Mikhail Vishnyakov (independent), Tatiana Gaintseva (QMUL). 27 pages, all read (main text, App. A–G, Tables 1–15).
Code: https://github.com/Atmyre/sv-detect/ (abstract). Note: App. B still says "We will release code ... upon acceptance", so the repo may be incomplete.

## Research question
Can a human-vs-AI separating direction, taken per layer from the hidden states of a *frozen* LM, serve as a robust
AI-text detection feature under distribution shift (domain, source LLM, editing/paraphrase attacks, cross-benchmark)?
Framing: "AI-text detection as a representation-space probing problem." **Detection only. No causal or steering claims.**

## Method (exact)
- **Backbone (probe LM)**: frozen **GPT-Neo-2.7B** (32 layers) for all main experiments. Ablations: Qwen3-1.7B, Qwen3-1.7B-Base,
  Gemma-3-1B-pt, Gemma-3-1B-it (App. C); Llama-2-7B (COLING, App. E); LLaMA-3.1-8B(-Instruct) (RAID vs RepreGuard, App. G).
- **Input**: texts truncated to 2048 tokens (512 for the latency benchmark). The text is fed raw: no chat template, and the text is not the model's own output.
- **Pooling**: mean-pool the residual hidden states over all tokens at every layer l, giving a_l(x) in R^d. Max/attention pooling is left to future work.
- **Steering vector v_l per layer** (unit-normalised). Three variants:
  1. Mean-difference: (mu_AI - mu_human)/||.|| (diff-of-means).
  2. **LogReg (default)**: normal vector of an L2 logistic regression fit on the layer's pooled activations.
  3. PCA: PC1 of the paired (AI - human) activation differences.
- **Projection features**: s_l(x) = <a_l(x), v_l>/||a_l(x)|| (cosine similarity), concatenated to s(x) in R^L (L x 3 or L x 4 for the "task-aware"
  multi-direction variants, which fit one direction per subtask and orthonormalise the set via QR).
- **Classifier**: StandardScaler + LogisticRegression (liblinear, C=1.0, seed 42) on the L features. It is trained on the same split used to build v_l.
  Ablations: KNN(k=5) and CatBoost (both worse under transfer).
- **Token-level attribution**: rho_t = <h_{l*}(x_t), v_{l*}> at the best-AUROC layer (Fig. 1).

## Datasets / splits / sizes
- **DetectRL** (Wu et al. 2024). Multi-Domain (ArXiv, XSum, Writing, Review): 50 AI samples per (llm,domain) cell. Multi-LLM (GPT-3.5, Claude, PaLM-2, Llama-2):
  200 per cell. Multi-Attack (Direct, Prompt, Paraphrase, Perturbation, Mixing): 10,192 human + 10,192 AI. Evaluation always uses the full test split.
- **MIRAGE** (Fu et al. 2025). Settings: DIG/SIG x GENERATE/POLISH/REWRITE. Training: **only 500 human/GPT-3.5-Turbo-POLISHED pairs**.
  Test sizes are about 15-16k per cell (e.g. DIG-generate 16,411).
  The extended variant adds 150 GENERATE and 150 REWRITE pairs from ImBD (union-800, 3-vec).
- **PADBen** (paraphrase laundering; 5 sentence-pair tasks): zero-shot target only.
- **RAID**: zero-shot target (TPR@5%FPR). Also trained on it for the RepreGuard comparison.
- **COLING-2025 MGT English**: 610,767 training texts (228,922 human, 381,845 AI, 27 generators), 261,758 dev, 73,941 test. They also test a "trimmed" pool with 20 weak generators removed.

## Baselines
Zero-shot: Log-Likelihood, Entropy, Rank, Log-Rank, LRR, NPR, DetectGPT, DNA-GPT, Revise-Detect, Binoculars, Fast-DetectGPT, RADAR, GLTR, LLMDet.
Supervised: RoBERTa-Base/Large, XLM-R-Base/Large, ImBD, DetectAnyLLM, RepreGuard. RepreGuard is the closest representation method and is re-implemented on GPT-Neo-2.7B.

## Metrics
AUROC, AUPR, TPR@FPR=5%, balanced accuracy, MCC, F1. Ablations report three numbers: in-distribution, mean off-diagonal transfer, and worst-case transfer AUROC.

## Key numbers
- **DetectRL in-distribution**: AUROC 99.8–100, F1 98.8–100 across all 13 cells. RoBERTa-Base is about the same (saturated).
  Binoculars gets 55–97. RepreGuard on GPT-Neo is about 50 (it collapses).
- **DetectRL cross-source (F1, Table 8)**:
  - Multi-Domain off-diagonal 75–97. The worst pair is XSum->Writing at 75.7. This is 7–14 F1 above RoBERTa-Base.
  - Multi-LLM 86.6–99.6 (GPT-3.5->PaLM-2 86.6, GPT-3.5->Claude 90.8).
  - Multi-Attack 91.7–99.1.
  - Cross-domain AUROC (GPT-Neo, Table 2): ArXiv->Writing 86.8, Writing->XSum 81.8. Qwen3-1.7B-Base is the best backbone (worst cell 94.0).
- **MIRAGE (AUROC, polish-500 training)**:
  - DIG: Generate 0.978, Polish 0.911, Rewrite 0.911. SIG: 0.978 / 0.909 / 0.904.
  - DetectAnyLLM wins on Polish/Rewrite (about 0.93/0.92).
  - The 3-vec task-aware variant gives 0.991 / 0.951 / 0.950.
  - Inconsistency: Table 3 lists SV-Detect MIRAGE AUROCs as 99.1 / 95.1 / 95.0, which match the 3-vec numbers rather than the default.
- **Cross-benchmark (grand-mean AUROC)**:
  - MIRAGE->DetectRL: 0.943 (RADAR 0.917, RoBERTa-L 0.866). Claude is the worst target (0.884).
  - DetectRL->MIRAGE: 0.894 (RoBERTa-L 0.918 is better). Polish/Rewrite targets about 0.85.
  - ->PADBen mean: 0.81–0.84 (RADAR 0.76). IPD is about 0.5 for every method.
- **RAID zero-shot TPR@5%**: Chat 65–79 but **Non-Chat (base-model generators: gpt2, mistral, mpt) only 9–34**.
  The authors say this is "consistent with our training data containing only chat-tuned model outputs". In other words, the direction is largely an instruct-model register.
- **RAID trained**: SV-Detect 99.7 TPR@5% / AUROC 0.9993 on both backbones. RepreGuard gets 4.9 (GPT-Neo) and 93.2 (LLaMA-8B).
- **COLING-2025**: Llama-2-7B LogReg reaches macro-F1 84.8 / Acc 85.0, rank 1 on the leaderboard (test AUROC 0.938). GPT-Neo gets F1 75.6 (test AUROC 0.866–0.873).
  Dev AUROC is 0.975 vs test 0.866 for GPT-Neo, a large dev-test gap.
- **Construction ablation** (DetectRL Multi-Domain transfer AUROC, Table 11):
  - LogReg: worst cell 81.8, mean off-diagonal about 92.5.
  - Mean-diff: worst cell 71.9 (ArXiv->Writing), mean about 86.
  - PCA: worst cell 50.8, mean about 78.
  - COLING test AUROC (GPT-Neo): Mean 0.860, PCA 0.751, LogReg 0.866. With Llama-2: Mean 0.912, LogReg 0.938.
  - So diff-of-means is close to LogReg in-distribution but worse under transfer.
- **Cost**: 25.7 ms/text, about the same as one log-likelihood forward pass.

## Interpretation analyses
- **Layer attribution** (|w_l|·sigma_l): on MIRAGE the signal concentrates at L29–31 (final layers). On DetectRL it is spread out, with peaks at L0–2
  (attributed to surface lexical cues), L14–18 and L21.
- **Logit-lens of v_l** (W_U·LN_f(v_l)). Readings are noisy and full of subword fragments.
  - LLM side (+v): formal/polished register, e.g. "utilizing", "endeavors", "paralleled", "foreseen".
  - Human side (-v): punctuation-heavy, colloquial and topical tokens ("Playstation", "organising").
- **Cross-LM consensus** (GPT-Neo, Qwen3-1.7B, Gemma-3-1B-pt/-it, last third of layers, top-8 tokens per layer):
  - +v in all 4 LMs: *endeavors, utilization, utilizing*. In 3 of 4: captivating, cybersecurity, leveraging, optimization, favorable, unfavorable.
  - -v: *anyway, basically, etc, maybe, really, very*.
  - This is effectively a "polished/formal vs casual" register axis.
- **Stylistic regex baseline** (LogReg on the feature bank below):
  - Feature bank: typography (em-dash, curly quotes, ellipsis), markdown, formal connectives (Moreover/Furthermore/Additionally/In conclusion/Overall),
    casual hedges (kinda/sorta/tbh), inclusive pronouns, "polished" lexicon (utilizing/endeavor/showcase), log length, prompt leakage/template artifacts, mid-word case flips.
  - Baseline AUROC: MIRAGE 76–82, DetectRL 88–91. SV-Detect improves on it by +13–24 points (MIRAGE) and +9–12 (DetectRL).
  - The authors read this gap as "signal beyond surface features". Caveat: the comparison is a regex bank vs a 2.7B-LM feature, in-distribution only.
    There is no control for formality/topic/length via the residual stream itself.
- **Per-token projections**: AI text shows localized spans with strong positive projections. Human text shows weaker, mixed projections (qualitative only).

## Do they ever STEER generation? **No.**
They say explicitly that the vectors are "of the same kind used in activation steering ... However ... in SV-Detect they are used only as probing and
classification features". There are no interventions, no ablations of the direction, and no generation experiments. Despite the name, there is no causal evidence.

## Confound controls (weak)
- Domain/source/attack are handled via cross-source transfer.
- MIRAGE SIG uses a shared input, which gives some topic matching. Polish/rewrite pairs preserve content, and these are the cleanest pairs.
- **Not controlled**:
  - Formality or register as a separate direction. Their own logit-lens says the direction *is* largely formal vs casual.
  - Length. Log length is in the regex bank but not residualized.
  - Topic.
  - Instruct vs base model, or assistant persona. RAID Non-Chat collapses, which hints the direction is a chat-model register.
- There is no comparison against a formality probe and no measurement of cosine with other directions.
- Questionable RepreGuard numbers: exactly 50.00 AUROC in many cells suggests degenerate reproduction.

## Limitations (stated and observed)
- Stated: depends on the probe LM; needs a full LLM forward pass; English only; document-level only; supervised, so it needs recalibration.
- Observed:
  - Some reported numbers are internally inconsistent (Table 3 vs Table 9).
  - Cross-domain into Writing is weak for GPT-Neo.
  - Base-model generators are poorly detected.
  - No causal tests.
  - A single seed for most results, with no CIs.

## Implications for our experiments
1. **Use paired, content-matched data to fit the direction.** Human text plus its LLM POLISH/REWRITE (MIRAGE-style, or generated by us) means the
   diff-of-means isolates style rather than topic. Just 500 polish pairs gave 0.91–0.98 AUROC with cross-benchmark transfer of about 0.94, so a few hundred pairs suffice.
2. **Fit both diff-of-means and LogReg directions**, mean-pooled per layer.
   - For detection, LogReg is more robust under transfer.
   - For steering, diff-of-means is usually the better intervention vector (LogReg normals pick up low-variance discriminative directions).
   - Report both, plus the cosine between them.
   - Expect separability to peak in mid-late layers (about L14–21 of 32, and the final layers for polish data). Sweep the steering layer at about 40–70% depth.
3. **This paper is the separability baseline (criterion a). Our novelty is (b), causality.** Inject alpha·v into the residual stream of an *instruct* model (Qwen3/Gemma-it).
   Measure detector score shifts with an independent detector: Binoculars/Fast-DetectGPT, a RoBERTa detector, and the SV-Detect-style probe trained on a *different* model.
   Measure content preservation and coherence with embedding similarity to the unsteered output, perplexity, and an LLM judge.
4. **Confound controls they skipped, which we must run (criterion c):**
   - Build formality (GYAFC-style formal/informal), domain, length and "assistant persona" (chat template vs no template; instruct vs base) directions.
   - Report cosine with the AI direction.
   - Project those directions out (or use LEACE) and re-test both AUROC and steering effect.
   - Their own logit-lens shows +v ≈ "utilize/endeavor/leverage" and -v ≈ "basically/maybe/really", so formality is the main suspect. Their regex gap (+9–24 AUROC) is not a residual-stream-level control.
5. **Lexical sanity check for steering**: count "utilize/leverage/endeavor/Moreover/em-dash" rates in steered outputs. If detector shifts are fully explained by these words,
   the direction is just a lexical style knob. A regex-feature detector like their D.3 bank makes a cheap "surface" detector to compare against.
6. **Base vs chat generalization**: RAID non-chat failure suggests the direction encodes instruct-tuned register. Test whether the direction found in a base model
   transfers to (and steers) the instruct model and vice versa.
7. **Token-level projection (rho_t)** is a cheap diagnostic. Use it to show where steering changes the per-token AI-score.
